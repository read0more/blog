# read0more 블로그

read0more의 개인 기술 블로그입니다. `content/posts/<카테고리>/`에 마크다운(`.md`) 파일을 추가하면 글이 되는 구조로 만들었습니다.

Next.js SSG로 구성하였습니다.

## 개발

```bash
npm install
npm run dev    # 개발 서버
npm run build  # 정적 export (out/)
```

## 글 쓰기

`content/posts/<카테고리>/` 폴더에 `.md` 파일을 추가하면 됩니다. `posts` 바로 아래 폴더 이름이 글의 대표 카테고리가 됩니다. 각 파일 맨 위에는 프론트매터(YAML)로 나머지 메타데이터를 적습니다.

```text
content/posts/
├── 루프팩과정/
│   ├── fsd-migration.md
│   └── wil/
│       └── wil-round1.md
└── 생각들/
    └── frontend-future.md
```

- 하위 폴더는 파일 정리 용도입니다. `루프팩과정/wil/wil-round1.md`의 카테고리는 `루프팩과정`입니다.
- 글 주소는 폴더와 무관하게 `/posts/<파일명>`입니다. 폴더를 옮겨도 주소는 유지됩니다.
- 파일명은 모든 카테고리를 통틀어 유일해야 합니다. 중복 파일명이나 `posts` 바로 아래의 `.md`는 빌드 오류로 처리됩니다. 이 검사는 초안에도 적용됩니다.
- frontmatter의 `category`는 사용하지 않습니다. 카테고리를 바꾸려면 파일을 이동하세요.

```markdown
---
title: "글 제목"
date: "2026-05-09T09:00:00.000Z"
description: "목록과 검색에 노출되는 한 줄 요약"
tags: ["React", "리팩토링"]
---

본문 시작...
```

- `title` — 글 제목
- `date` — 작성일(ISO 8601). 목록 정렬 기준
- `description` — 글 목록·검색 결과에 보이는 요약
- `tags`: (선택) 세부 주제 태그 배열. 글 카드와 글 상세에 `#태그` 칩으로 보이고 `/tag/태그명` 목록으로 연결됩니다
- `draft` — (선택) `true`면 **배포 시 제외**되는 초안. 생략하거나 `false`면 공개 글

### 영어 번역

원문 옆에 같은 파일명으로 `.en.md`를 추가합니다. 예를 들어 `생각들/live-code-demo.md`의 번역은 `생각들/live-code-demo.en.md`입니다. 번역은 원문과 같은 디렉토리에 있어야 하며, 원문 없이 번역만 두면 빌드 오류가 납니다. `.en` 접미사는 영어 번역용으로 예약되어 있습니다.

```markdown
---
title: "Live Code Block Preview"
description: "A preview of code blocks running inside the blog."
draft: true
---

English content...
```

- 번역에는 `title`, `description`, 영어 본문을 작성합니다. 카테고리·작성일·태그는 원문에서 가져오므로 번역에 중복 작성하지 않습니다.
- 한국어 홈은 `/`, 영어 홈은 `/en/`입니다. 원문 주소는 `/posts/live-code-demo/`, 영어 주소는 `/en/posts/live-code-demo/`입니다. 직접 접근과 새로고침도 지원합니다.
- 언어 전환은 헤더의 **English / 한국어** 하나로 통합합니다. 번역이 있는 글에서는 같은 글의 다른 언어로 이동하고, 홈·목록에서는 해당 언어 홈으로 이동합니다. 글 안의 별도 EN/KO 버튼은 없습니다.
- 한국어 전용 글에서는 헤더를 **English home**으로 표시하여 영어 홈으로 이동함을 명시합니다.
- 번역 없는 글의 `/en/posts/<slug>/`에 직접 접근하면 짧은 영어 안내와 한국어 원문 링크를 제공합니다. 한국어 본문을 영어 글처럼 노출하지 않으며, 안내 페이지는 검색 엔진 색인에서 제외합니다. 존재하지 않는 글과 배포에서 제외한 초안은 계속 404입니다.
- 한국어 목록·카테고리·태그·검색은 원문을, 영어 화면은 번역본만 집계합니다. 루프팩과정 글처럼 영어로 제공하고 싶지 않은 글은 `.en.md`를 만들지 않으면 됩니다. 번역이 없는 카테고리·태그도 영어 화면에 나타나지 않습니다.
- `draft: true`인 번역은 배포에서 영어만 제외됩니다. 원문이 초안이면 번역도 함께 제외됩니다. 로컬에서는 기존 규칙대로 초안도 미리 볼 수 있습니다.
- 영어 화면의 메뉴·검색·날짜·목차·코드 복사·라이브 코드 보기 버튼·댓글 안내도 영어로 표시합니다.
- 카테고리·태그 식별자와 원문 메타데이터는 유지하고 `messages/ko.json`, `messages/en.json`의 `taxonomy`에서 표시명을 관리합니다. 예: `생각들 → Thoughts`, `렌더링 → Rendering`. 등록하지 않은 이름은 원래 이름을 사용하므로 새 한글 분류의 번역을 공개할 때 표시명도 추가하세요.
- 원문 완성 후 번역 초안을 작성하고 검토한 뒤 공개합니다. 원문 수정 시 번역 파일도 직접 갱신합니다. 빌드 시 자동 번역하지 않습니다.

`npm run test:translations`는 실제 `live-code-demo` 원문·번역을 `/blog` 경로로 빌드하여 데스크톱과 모바일에서 검사합니다. 두 데모는 원문의 `draft: true` 설정에 따라 배포되지 않습니다. 이 명령은 일반 E2E와 같은 빌드 디렉토리를 사용하므로 순서대로 실행하세요.

### GitHub Pages와 영어 사이트

#### UI 번역 관리

포스트 번역과 별개로 일반 문구는 [use-intl](https://next-intl.dev/docs/environments/core-library)(next-intl의 공식 코어 라이브러리)로 관리합니다.

- `messages/ko.json`, `messages/en.json`의 `ui`에 동일한 키로 문구를 추가합니다. 컴포넌트는 `getUiTranslator(language)("search")`처럼 호출합니다. UI 키는 TypeScript가 검사합니다.
- 변수와 복수형은 ICU 메시지로 작성합니다. 예: `{count, plural, one {# post} other {# posts}}`. 호출은 `translate("postCount", { count })`입니다. 문장 조각을 코드에서 조합하거나 언어별 복수형 함수를 작성하지 않습니다.
- `npm run check:messages`가 키 일치, 빈 문구, ICU 구문과 변수 일치를 검사합니다. `dev`와 `build` 전에 자동 실행하므로 한국어에만 키를 추가하면 실패합니다.
- 날짜는 라이브러리의 `createFormatter`로 처리하며 UTC를 명시합니다. 서버와 브라우저의 로컬 시간대에 영향을 받지 않습니다.
- `createTranslator`에 언어와 메시지를 명시적으로 전달합니다. 요청 기반 설정이나 Provider 없이 정적 서버 렌더링·클라이언트·독립 라이브 코드 루트·검색 빌드가 같은 카탈로그를 사용합니다. 경로는 기존 정적 라우트를 유지합니다.
- 라이브러리는 문구를 자동으로 번역하지 않습니다. 영어 문구는 JSON에 직접 작성하고, 포스트 본문은 기존 `.en.md`로 관리합니다.

모든 언어의 페이지는 `output: export`로 HTML을 생성합니다. 검색도 빌드 시 생성하는 `search-index.json`(한국어), `search-index.en.json`(영어)을 브라우저에서 검색하므로 서버가 필요하지 않습니다. 공개 영어 번역이 0개여도 `/en/`은 안내 문구와 빈 검색 인덱스를 제공합니다.

기존 `/posts/<slug>/en/` 주소에는 새 영어 주소로 이동하는 정적 안내 페이지를 생성합니다. JavaScript가 켜져 있으면 쿼리와 해시를 유지하여 자동 이동하며, 꺼져 있어도 이동 링크를 사용할 수 있습니다. HTTP 301/302 리다이렉트나 서버 미들웨어를 사용하지 않습니다.

언어별 루트 레이아웃은 처음 내려오는 HTML부터 `lang="ko"` / `lang="en"`을 제공합니다. GitHub Pages의 공통 `404.html`은 브라우저 주소에 따라 안내 언어를 선택하며, JavaScript가 꺼져 있으면 영어 홈으로 돌아가는 안내 링크를 함께 제공합니다.

`npm run build`의 `postbuild`에서 페이지·언어별 인덱스·기존 주소 링크·초안 제외 산출물을 자동 검사합니다. 배포와 같은 조건은 `OMIT_DRAFTS=true BASE_PATH=/blog npm run build`로 확인할 수 있습니다.

### 테스트 계층

- `npm run test:unit`: Vitest로 ICU 복수형·날짜·분류 표시명과 카탈로그 오류를 검증합니다.
- `npm run test:integration`: Node에서 콘텐츠·검색 인덱스의 번역/초안 규칙을, RTL + MSW에서 목록·번역 링크 노출·검색 입력/빈 결과/취소를 검증합니다.
- `npm test`: 위 두 계층만 실행합니다. Next 빌드·서버·실제 브라우저가 필요하지 않습니다.
- `npm run test:translations`: 실제 `/blog` 정적 산출물에서 언어 전환/새로고침·옛 주소 이동·JS 없는 탐색·404 복귀와 모바일 메뉴/검색 흐름을 검증합니다. 문구별 비교나 파일/JSON 개수 검증은 E2E에서 하지 않습니다.

E2E에 추가하려면 **통합 테스트로 확인할 수 없는 이유**가 있어야 합니다. 영어 기능에서는 실제 문서 탐색·브라우저 이동·초기 HTML·CSS에 따른 모바일 조작 가능성을 보호합니다. 단순 표시 문자열과 데이터 규칙은 빠른 계층에 두고, 동일 시나리오의 데스크톱/모바일 중복 실행은 피합니다. 실제 트래픽 비율을 수집하지 않았으므로 트래픽 커버리지 수치를 주장하지 않습니다.

### 초안(draft) — 배포에서 제외하기

아직 공개하고 싶지 않은 글이나 테스트용 더미 글은 프론트매터에 `draft: true`를 답니다.

```markdown
---
title: "아직 공개 전인 글"
date: "2026-05-09T09:00:00.000Z"
description: "..."
draft: true
---
```

- **로컬**(`npm run dev` / `npm run build`)과 **E2E 테스트**에서는 `draft` 글도 그대로 보입니다. 작성 중 미리보기와 테스트 픽스처를 위해서입니다.
- **GitHub Actions 배포**에서만 `draft: true` 글이 사이트(`out/`)와 검색 인덱스에서 빠집니다. 배포 워크플로(`.github/workflows/deploy.yml`)의 빌드 스텝에 `OMIT_DRAFTS=true`가 주입되어 있고, 이 값이 있을 때만 초안을 거릅니다.
- 글을 공개하려면 `draft` 줄을 지우거나 `draft: false`로 바꾸면 됩니다.

> ⚠️ 공개 글이 하나도 없는 상태(모든 글이 `draft: true`)로 배포하면 정적 export 특성상 빌드가 실패합니다. 실제 글을 최소 하나 둔 뒤 배포하세요.

### 카테고리 색상

카테고리는 글이 있는 최상위 폴더에서 자동으로 수집되어 사이드바에 표시됩니다. 배포에서 제외된 초안만 있는 폴더는 배포 카테고리에 나타나지 않습니다.

카테고리 색은 따로 지정하지 않습니다. 카테고리 이름을 해시 함수에 넣어 미리 정해둔 몇 가지 색(iOS 시스템 컬러 팔레트) 중 하나를 결정적으로 골라 쓰는 방식입니다. 덕분에 새 카테고리도 항상 같은 색으로 안정적으로 표시됩니다.
