# read0more 블로그

read0more의 개인 기술 블로그입니다. `content/posts/<카테고리>/`에 마크다운(`.md`) 파일을 추가하면 글이 되는 구조로 만들었습니다.

Next.js SSG로 구성하였습니다.

## 개발

```bash
npm install
npm run dev    # 개발 서버
npm run build  # 정적 export (out/)
```

## 글 쓰기

`content/posts/<카테고리>/` 폴더에 `.md` 파일을 추가하면 됩니다. `posts` 바로 아래 폴더 이름이 글의 대표 카테고리가 됩니다. 각 파일 맨 위에는 프론트매터(YAML)로 나머지 메타데이터를 적습니다.

```text
content/posts/
├── 루프팩과정/
│   ├── fsd-migration.md
│   └── wil/
│       └── wil-round1.md
└── 생각들/
    └── frontend-future.md
```

- 하위 폴더는 파일 정리 용도입니다. `루프팩과정/wil/wil-round1.md`의 카테고리는 `루프팩과정`입니다.
- 글 주소는 폴더와 무관하게 `/posts/<파일명>`입니다. 폴더를 옮겨도 주소는 유지됩니다.
- 파일명은 모든 카테고리를 통틀어 유일해야 합니다. 중복 파일명이나 `posts` 바로 아래의 `.md`는 빌드 오류로 처리됩니다. 이 검사는 초안에도 적용됩니다.
- frontmatter의 `category`는 사용하지 않습니다. 카테고리를 바꾸려면 파일을 이동하세요.

```markdown
---
title: "글 제목"
date: "2026-05-09T09:00:00.000Z"
description: "목록과 검색에 노출되는 한 줄 요약"
tags: ["React", "리팩토링"]
---

본문 시작...
```

- `title` — 글 제목
- `date` — 작성일(ISO 8601). 목록 정렬 기준
- `description` — 글 목록·검색 결과에 보이는 요약
- `tags`: (선택) 세부 주제 태그 배열. 글 카드와 글 상세에 `#태그` 칩으로 보이고 `/tag/태그명` 목록으로 연결됩니다
- `draft` — (선택) `true`면 **배포 시 제외**되는 초안. 생략하거나 `false`면 공개 글

### 초안(draft) — 배포에서 제외하기

아직 공개하고 싶지 않은 글이나 테스트용 더미 글은 프론트매터에 `draft: true`를 답니다.

```markdown
---
title: "아직 공개 전인 글"
date: "2026-05-09T09:00:00.000Z"
description: "..."
draft: true
---
```

- **로컬**(`npm run dev` / `npm run build`)과 **E2E 테스트**에서는 `draft` 글도 그대로 보입니다. 작성 중 미리보기와 테스트 픽스처를 위해서입니다.
- **GitHub Actions 배포**에서만 `draft: true` 글이 사이트(`out/`)와 검색 인덱스에서 빠집니다. 배포 워크플로(`.github/workflows/deploy.yml`)의 빌드 스텝에 `OMIT_DRAFTS=true`가 주입되어 있고, 이 값이 있을 때만 초안을 거릅니다.
- 글을 공개하려면 `draft` 줄을 지우거나 `draft: false`로 바꾸면 됩니다.

> ⚠️ 공개 글이 하나도 없는 상태(모든 글이 `draft: true`)로 배포하면 정적 export 특성상 빌드가 실패합니다. 실제 글을 최소 하나 둔 뒤 배포하세요.

### 카테고리 색상

카테고리는 글이 있는 최상위 폴더에서 자동으로 수집되어 사이드바에 표시됩니다. 배포에서 제외된 초안만 있는 폴더는 배포 카테고리에 나타나지 않습니다.

카테고리 색은 따로 지정하지 않습니다. 카테고리 이름을 해시 함수에 넣어 미리 정해둔 몇 가지 색(iOS 시스템 컬러 팔레트) 중 하나를 결정적으로 골라 쓰는 방식입니다. 덕분에 새 카테고리도 항상 같은 색으로 안정적으로 표시됩니다.
