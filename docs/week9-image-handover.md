## 1. initial-user-tree-gap.png

- **본문 위치**: `### 로그인 상태를 초기 HTML에 넣기: 만들어놓고 접은 것` 안, "그건 정적 예산을 통째로 내놓는 선택이라 그때는 피하고 싶었다" 문단 뒤
- **유형**: 생성
- **alt**: `루트 레이아웃이 쿠키를 읽지 않고 헤더 쪽에서 initialUser를 만들기 때문에, 그보다 위에 있는 AnalyticsIdentity까지 값이 닿지 않는 트리 구조. 루트에서 읽으면 닿지만 모든 라우트가 동적이 된다`
- **이 그림이 답해야 하는 질문**: "헤더에 준 `initialUser`를 `AnalyticsIdentity`에도 그냥 주면 되지 않나?" 답은 "값이 태어난 자리가 헤더라서 위로 못 올린다"이고, 이어서 "그럼 루트에서 읽으면 되지 않나?"의 답이 "닿긴 하는데 정적 예산을 전부 내놓는다"다. **세로 위치가 곧 논지**이니 위아래 순서를 정확히 지킬 것.
- **구도**: 위에서 아래로 내려가는 컴포넌트 트리 한 장. 문제 상황을 그리는 그림이라 전체 톤은 빨강 계열. 좌상단에 상태 배지 `고치기 전`.
- **트리 구조와 라벨**:
  - 최상단 `app/layout.tsx` (남색). 바로 옆에 회색 라벨 `쿠키를 읽지 않는다`
  - 그 아래 `Providers`
  - `Providers` 아래 두 갈래
    - 왼쪽 가지: `AnalyticsIdentity` · 작은 라벨 `useSession() 호출 · 초기값 없음` · 여기서 빨간 화살표가 옆으로 나가 `/api/auth/me` 박스로 이어지고 그 끝에 빨간 배지 `401`
    - 오른쪽 가지: `CommerceHeader` · 그 아래 `CommerceHeaderAuth` · 초록 배지 `여기서 쿠키를 읽어 initialUser를 만든다`
  - 오른쪽 `CommerceHeaderAuth`에서 왼쪽 `AnalyticsIdentity`로 **올라가려는** 점선 화살표를 그리고 그 위에 빨간 X. 화살표 옆 라벨: `값이 태어난 자리가 아래다. props·context는 위로 못 올라간다`
  - 최상단 `app/layout.tsx`에서 아래로 내려오는 **회색 점선** 화살표를 하나 더 그린다. 이건 아직 안 고른 길이라 빨강도 초록도 아닌 회색. 옆 라벨 두 줄: `여기서 읽으면 닿는다` / `대신 라우트 15개가 전부 동적`
- **강조**: 세로 위치가 논지의 전부다. `AnalyticsIdentity`가 `CommerceHeader`보다 확실히 위에 놓이도록, 두 가지의 첫 박스 높이를 눈에 띄게 어긋나게 배치할 것. 좌우로만 갈라서 같은 높이에 두면 그림이 하려는 말이 사라진다.
- **넣지 말 것**: `HydrationBoundary`, 세션 캐시 시드, 힌트 쿠키 관련 요소. 본문에서 뺀 내용이다.

## 4. login-guard-signal-mismatch.png

- **본문 위치**: `### 로그인 화면 차단을 proxy에서 세션으로 옮긴 이유` 마지막 문단 뒤
- **유형**: 생성. **이미 생성된 파일이 있다면 반드시 다시 만들 것.** 이전 사양에 `proxy가 보는 것: 쿠키 서명`이라고 적혀 있었는데 그게 사실과 다르다. proxy는 서명뿐 아니라 만료 시각까지 검증한다. 아래 라벨로 새로 생성해야 한다.
- **alt**: `쿠키를 읽어 판정하는 proxy와 서버 응답을 보는 앱 세션이 만료 상황에서 서로 다른 답을 내면서, 만료 감지 후 로그인으로 보낸 사용자가 다시 보호 경로로 되돌려지는 흐름`
- **이 그림의 논지**: proxy가 **덜 검증해서** 생긴 어긋남이 아니다. proxy는 쿠키가 말해주는 걸 전부 본다. 다만 이 만료가 **쿠키에 적혀 있지 않아서** 쿠키를 읽는 자리에서는 알 수 없는 것이다. 그림이 "proxy는 대충 보고 앱은 꼼꼼히 본다"로 읽히면 실패다. "둘은 서로 다른 것을 읽는다"로 읽혀야 한다.
- **구도**: 위쪽에 만료 상태를 나타내는 박스 하나를 두고, 거기서 두 갈래로 내려가 서로 다른 판정을 내는 그림. 아래쪽에 그 어긋남이 만드는 순환을 화살표로 그린다.
- **라벨(정확히 이대로)**:
  - 맨 위 박스 (노랑 또는 주황): `만료 시나리오: 쿠키는 서명·만료 모두 유효, 서버 응답만 401`
  - 왼쪽 갈래 (남색, proxy): 제목 `proxy가 읽는 것` · 내용 `세션 쿠키 (서명·만료 시각 모두 검증)` · 판정 배지 `멀쩡한 토큰이다`
  - 오른쪽 갈래 (청록, 앱): 제목 `앱 세션이 읽는 것` · 내용 `/api/auth/me 응답` · 판정 배지 `만료됐다`
  - 두 판정 사이에 빨간 번개 또는 충돌 표시와 라벨 `읽는 것이 다르니 답이 갈린다`
  - 아래쪽 순환 화살표 3단계: `앱이 만료를 감지해 /login으로 보냄` → `proxy가 멀쩡한 쿠키를 보고 보호 경로로 되돌림` → `복원 흐름이 깨짐` (마지막에 빨간 배지)
- **주의 1**: 위조 쿠키 이야기가 아니다. 그림에 `위조`, `변조`, `서명 실패` 같은 라벨을 넣지 말 것. 쿠키는 완전히 정상이라는 게 이 그림의 전제다.
- **주의 2**: proxy 쪽 라벨에 `서명만`, `대충`, `가볍게` 같은 말을 넣지 말 것. 사실과 다르고 논지를 뒤집는다.

## 10. defense-map.png

- **본문 위치**: `### 무엇이 무엇을 지키는지 먼저 확인했다` 안, 세 개 불릿과 "유닛이 원리적으로 못 보는 자리, 유닛도 E2E도 보는 자리, 아무 테스트도 안 만들어둔 자리가 하나씩이다" 줄 뒤
- **유형**: 생성. **이미 생성된 파일이 있다면 반드시 다시 만들 것.** 실험 2 대상이 `세션 쿠키 httpOnly`에서 `로그인 후 복원 이동`으로 바뀌었고, 행 구성과 캡션이 통째로 달라졌다. 본문이 401 만료 분기를 실험 후보로 다루지 않게 되면서 그 행도 뺐다.
- **alt**: `검증 대상마다 유닛·통합·E2E 중 무엇이 지키고 있는지 표시한 표. E2E만 덮는 자리, 유닛도 같이 덮는 자리, 아무 테스트도 없는 빈자리가 갈린다`
- **이 그림의 논지**: 최종 실험 대상 셋이 **서로 다른 갈래**라는 게 표에서 보여야 한다. `config.matcher`와 `초기 HTML 세션 주입`은 유닛·통합이 비어 있고 E2E만 채워진다. `로그인 후 복원 이동`은 유닛과 E2E가 함께 채워진다. 이 대비가 그림의 목적이다.
- **구도**: 행이 검증 대상, 열이 테스트 계층인 격자 표. 덮는 칸은 색으로 채우고, 안 덮는 칸은 빈칸으로 둔다.
- **표 위 캡션(반드시 넣을 것)**: `이 지점을 망가뜨리면 어디가 잡히나`. 이 한 줄이 없으면 독자가 "덮는 계층 전부"로 오해한다. 예를 들어 `복원 경로 정제`는 E2E도 그 코드를 지나가지만, 망가뜨렸을 때 잡히는 건 유닛이라 유닛만 채운다.
- **열 라벨**: `유닛` · `통합` · `E2E`
- **행 라벨과 채움**:

  | 행                             | 유닛 | 통합 | E2E  |
  | ------------------------------ | ---- | ---- | ---- |
  | `config.matcher`               |      |      | 채움 |
  | `로그인 후 복원 이동`          | 채움 |      | 채움 |
  | `초기 HTML 세션 주입`          |      |      | 채움 |
  | `proxy()` 가드 본문            | 채움 |      | 채움 |
  | `복원 경로 정제(safeRedirect)` | 채움 |      |      |
  | `세션 쿠키 httpOnly`           |      | 채움 |      |

- **강조**: 최종 실험 대상 세 행(`config.matcher`, `로그인 후 복원 이동`, `초기 HTML 세션 주입`)에 `실험 대상` 배지를 붙인다. 본문이 부르는 이름과 행 이름이 같으니 별도 연결 라벨은 필요 없다.
- **빈 칸 라벨**: `세션 쿠키 httpOnly` 행의 빈 E2E 칸에만 작은 라벨 `얹혀 있던 단언을 지워 비었다`를 넣는다. 본문이 그 삭제를 따로 다룬다. 다른 빈칸에는 라벨을 넣지 않는다.
- **주의**: `복원 경로 정제(safeRedirect)`와 `로그인 후 복원 이동`은 **다른 행이다. 절대 합치지 말 것.** 정제는 돌려보낼 경로를 걸러내는 함수고 E2E가 안 덮는다. 이동은 로그인 뒤 실제로 그 경로로 보내는 부분이고 E2E가 덮는다. 합치면 실험 2가 왜 유닛·E2E 둘 다에 잡혔는지가 설명되지 않는다.
- **주의 2**: 이 표는 `httpOnly` 단언을 지운 **뒤** 상태다. 이전 사양에 있던 `실험 전 시점`이라는 캡션 단서는 쓰지 말 것.

## 11. history-race-timeline.png

- **본문 위치**: `### 내가 빠뜨린 줄을 뮤테이션 탓으로 봤다` 안, "단언이 없는 구간이라 눈이 덜 갔다" 문단 뒤
- **유형**: 생성. **이미 생성된 파일이 있다면 다시 만들 것.** 이전 사양은 캡션이 라이브러리 동작을 원인으로 지목했는데, 본문이 "원인은 한쪽에만 대기를 안 넣은 것"으로 바뀌었다.
- **alt**: `같은 파일의 두 테스트 비교. 뒤로 가기 전에 URL 반영을 기다리는 첫 번째 테스트와, 그 대기가 빠져 히스토리 스택이 전제와 어긋나는 두 번째 테스트의 타임라인`
- **이 그림의 논지**: 스로틀은 원인이 아니라 **결함이 드러나게 만든 조건**이다. 원인은 같은 파일 안에서 한쪽 테스트에만 대기를 넣어둔 것이다. 그림이 "라이브러리 때문에 깨졌다"로 읽히면 실패다. **두 줄을 나란히 놓았을 때 위 줄에만 있는 상자 하나가 눈에 들어와야 한다.**
- **구도**: 가로 시간축 위에 두 줄의 타임라인을 위아래로 놓는다. 두 줄 모두 왼쪽 끝이 같은 시점. 시간축 시작 부분에 회색 밴드를 깔고 라벨 `nuqs 가 히스토리 쓰기를 묶어두는 50ms`.
- **위 줄 (초록, 통과)**: 제목 `첫 번째 테스트`. 이벤트 순서: `카테고리 변경` → (밴드 끝나고) `URL 반영을 기다림` → `뒤로 가기` → 끝에 초록 배지 `통과`
- **아래 줄 (빨강, 흔들림)**: 제목 `두 번째 테스트`. 이벤트 순서: `카테고리 변경` → (밴드 안에서 바로) `뒤로 가기` → 빨간 배지 `히스토리 스택이 전제와 어긋남`
- **강조**: 위 줄의 `URL 반영을 기다림` 상자와, 아래 줄에서 그 자리가 비어 있다는 것을 대비시킨다. 아래 줄의 빈자리에 점선 상자와 라벨 `이 줄이 빠져 있었다`를 둔다.
- **아래 캡션 라벨**: `같은 파일에 정답이 이미 있었다`
