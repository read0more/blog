# 테스트 계층 재검토 (2026-10-23)

## 결정 기준

8주차 테스트·RTL 자료, 9주차 E2E·시각적 회귀 자료와 발제 원본을 종합했다. 사용자 결과, 실패 비용, 더 낮은 계층에서 같은 회귀를 잡을 수 있는지를 기준으로 삼았다. 실제 세션 통계는 없으므로 트래픽 커버율은 주장하지 않는다. 이 블로그에서 글 발견·읽기·언어 이동을 주요 경로로 간주했다.

- **Node 유닛:** 검색어 정규화·매칭·스니펫, 기존 번역·날짜 규칙.
- **통합:** 실제 파일 → 페이지 함수 → RTL 렌더링, 분류·태그·정렬, 마크다운 파이프라인, 목차 표시 조건, 검색 훅 + MSW, 라이브 코드 파싱·보기 전환.
- **E2E:** 실제 정적 URL·새로고침·history, 브라우저 리다이렉트, `/blog` 검색 자산 경로와 모바일 조작, 실제 스크롤과 모션 감소 접근성. 브라우저 API를 호출한다는 사실만으로 유지하지 않는다.
- **삭제:** 특정 색상값, 단순 표시를 중복하는 스모크, 모바일 복제, 동일 PostList 전환을 화면별로 반복하는 검사. 삭제한 테스트를 전부 하위 테스트로 재생산하지 않았다.

실행 전 일반 E2E는 **44개**, 별도 번역 E2E는 **6개**였다. 첫 검토에서 총 14개로 줄였으나, 브라우저 사용 여부에 비해 테스트의 추가 가치를 느슨하게 판단했다. 두 번째 검토 후 **총 50개 → 5개**다. 유닛·통합은 **33개 → 49개**이며 새 의존성은 추가하지 않았다.

## 남았던 14개의 필요성 재검토

“해당 기능이 중요하다”와 “그 기능의 모든 속성을 CI에서 E2E로 검사해야 한다”는 다르다. 사용자 결과가 같으면 언어·화면별 복제를 지운다. 외부 API에 올바른 데이터를 넘기는 목적은 API 경계만 대체한 통합 테스트로 충분할 수 있다. CSS·브라우저 동작을 포기한 경우 같은 보증으로 이동했다고 표현하지 않는다.

번호는 사용자에게 설명했던 14개 목록의 순서다.

| #   | 이전 검증                                 | 최종 판단과 이유                                                                                                                                                                                                                                                                              |
| --- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 분류 → 글 → 한글 태그 → 새로고침          | **E2E 유지.** 콘텐츠 진입의 대표 경로. RTL의 href 검사는 export 경로·Next 탐색·한글 URL 서빙 실패를 못 잡는다. 뒤로가기 결과도 여기서 확인한다.                                                                                                                                               |
| 2   | 한국어 검색 → 글 → Sandpack 파일 탭       | **독립 E2E 삭제.** 검색 입력은 기존 RTL/MSW, 실제 인덱스 fetch·결과 클릭은 #14와 같은 훅/파이프라인이다. `live-code` 통합을 실제 markdown → ArticleClient → 동적 import → LiveCode → SDK 입력까지 확장했다. 실제 외부 SDK 탭/iframe 실행 보증은 의도적으로 내려놓는다.                        |
| 3   | 목차·복사·scroll-spy·맨 위로              | **스크롤 E2E만 유지, 복사는 통합.** 본문 DOM 교체·목차 잠금·말단 heading 추적의 비자명한 회귀를 실제 레이아웃에서 보호한다. 복사는 OS 대신 user-event 클립보드 경계로 올바른 본문 전달을 확인한다. OS 권한·클립보드 구현은 보호 대상에서 제외한다.                                            |
| 4   | 라이트박스 열기·이미지 크기·Escape·포커스 | **E2E 삭제, 이미지 어댑터만 통합.** SDK의 일반 개폐·포커스 동작을 매번 재검증할 추가 가치가 낮다. 우리가 작성한 로드 전 표시 크기/로드 후 원본 크기 전달은 실제 Markdown·ArticleClient·훅과 SDK 경계로 확인한다. 실제 SDK 로딩·브라우저 포커스는 자동 보증하지 않는다.                        |
| 5   | 일반 공유 전환·history                    | **삭제.** 제목·날짜·분류가 각각 애니메이션되는 모습은 읽기 기능을 차단하지 않는다. 일반 탐색·history는 #1로 보호하며 효과별 시간·pseudo-element 검사는 재생산하지 않는다.                                                                                                                     |
| 6   | 모션 감소 시 전환 제거                    | **E2E 유지.** 장식 효과가 아니라 사용자의 모션 감소 요청을 무시하지 않는 접근성 계약이다. jsdom이나 CSS 문자열 검사는 실제 미디어 설정·cascade·native 전환 시간을 검증하지 못한다.                                                                                                            |
| 7   | View Transitions API 삭제 후 탐색         | **삭제.** 앱 자체의 미지원 분기가 없고 React/Next가 호환성을 담당한다. Chromium에서 API만 지우는 검사는 실제 미지원 브라우저를 대표하지도 않는다. 일반 탐색은 #1·#14가 보호한다.                                                                                                              |
| 8   | 모바일 목차 이동                          | **E2E 삭제, 기존 통합 확장.** 모바일 고유 계약인 펼침 → 항목 선택 → 접힘·해시·활성 항목을 ArticleClient 통합에서 검증한다. 공통 스크롤은 #3, 모바일 CSS 위치·sticky 간섭은 별도 자동 보증하지 않는다.                                                                                         |
| 9   | 글 언어 왕복·새로고침                     | **독립 E2E 삭제.** 전환 대상 결정은 기존 유닛/RTL. 언어 경계를 넘는 실제 문서 이동은 #14에 이미 있다. 영어 상세 새로고침 후 본문 확인만 그 읽기 흐름에 추가한다.                                                                                                                              |
| 10  | legacy 주소 자동 이동·query/hash          | **E2E 유지.** 정적 export라 HTTP 리다이렉트가 없고 앱의 effect가 이동한다. location.replace 인자 검사는 통합으로 가능하지만 JS 로딩 후 실제 목적지 문서 도착을 보증하지 못한다. 호환 URL 계약 하나만 남긴다.                                                                                  |
| 11  | 한국어 404 → 한국어 홈                    | **E2E 삭제.** #12와 공통 컴포넌트이며 한 언어별 재실행의 추가 가치가 낮다. home href 후 실제 Link 이동은 일반 탐색과 중복이다.                                                                                                                                                                |
| 12  | 영어 404 → 영어 홈                        | **E2E 삭제, hydration 통합 1개로 대체.** 실제 GlobalNotFoundView를 SSR한 한국어 HTML에서 시작해 영어 URL로 hydration한다. 양 언어의 데이터/복귀 href와 html lang 전환을 함께 보호한다. 로컬 serve-handler의 HTTP 404 검사는 GitHub Pages 배포 동작의 보증이 아니다.                           |
| 13  | JS 없이 언어·legacy·미번역 링크 탐색      | **독립 E2E 삭제.** 링크는 JS 없는 일반 앵커이고 핵심 계약은 export HTML에 읽을 본문과 올바른 href가 존재하는 것이다. postbuild에서 실제 HTML DOM의 본문·언어/legacy 링크를 검사하고 기존 미번역 산출물 검사도 유지한다. JS-disabled 브라우저의 모든 클릭 가능성까지 동등하게 보증하지 않는다. |
| 14  | 모바일 언어·메뉴·검색 → 글 → 원문         | **E2E 유지.** 대표 글 발견 경로 하나로 `/blog` 인덱스 서빙·hydration·CSS 오버레이 클릭 가능성·실제 라우팅을 연결한다. RTL이 검증하는 입력/결과 상태와 목적이 다르다.                                                                                                                          |

11·12번은 **완전히 같은 입력은 아니지만 E2E 유지 근거는 중복**이었다. 영어 경로에서는 한국어 SSR 결과가 클라이언트에서 바뀐다는 고유 위험이 있다. 이 위험은 브라우저 서버까지 올리지 않아도 React의 실제 SSR/hydration으로 재현할 수 있으므로, 영어 E2E 한 개를 대표로 남기는 결정도 필요 이상이었다.

남긴 5개가 기술적으로 영원히 하향 불가능하다는 뜻은 아니다. #3·#6은 실제 브라우저 컴포넌트 통합으로 분리할 수 있지만, 그 실행 환경을 새로 운영하는 비용이 있다. 현재는 기존 Playwright의 5개 중 두 개로 유지한다. 나머지 세 개는 정적 빌드와 앱의 문서 탐색이 검증 대상이다. 전환·라이트박스 외부 SDK 보증 등을 삭제한 만큼 테스트 범위도 실제로 줄었다.

## 번역 E2E와 CI

번역 폴더는 legacy 실제 이동과 모바일 글 발견·언어 이동 **2개**만 남겼다. 404 두 건, no-JS, 별도 글 언어 왕복은 위 판단에 따라 제거했다.

이제 두 테스트 묶음 모두 `tests/fixtures/posts`를 `BASE_PATH=/blog`, `OMIT_DRAFTS=false`로 **한 번 빌드**한다. 실제 글을 고정 테스트 데이터로 사용하지 않는다. 기존 번역의 live-code-demo 종속은 번역된 use-effect 픽스처로 바꿨고, 라이브 코드의 앱 연결은 RTL 통합이 검증한다.

- `npm test`: 브라우저·Next 빌드 없이 전체 유닛/통합 실행.
- `npm run test:e2e`: 일반·번역 5개 전체, 픽스처 빌드 1회.
- `npm run test:translations`: 번역 폴더 2개만 확인하는 로컬 명령. CI에서는 중복 실행하지 않음.
- CI 전체 빌드: **3회 → 2회**(공통 E2E 픽스처 + 실제 콘텐츠 배포 빌드).
- 배포 빌드의 `OMIT_DRAFTS=true`, `verify-static-export.mjs`, 품질 게이트는 유지.
- CI 워커는 2개로 명시하고 재시도 1회는 유지. GitHub와 HTML 리포터를 함께 사용하고 보고서·실패 화면·trace를 업로드한다. 이전에는 HTML 보고서를 만들지 않으면서 그 폴더만 업로드하고 있었다.

## 의도적으로 보증하지 않는 범위

픽셀 회귀 기준선은 새로 만들지 않았다. 기존 `page.screenshot()`은 비교 단언이 없었으므로 제거했다. 특정 색상·카드 폭·모바일 전환 이미지, 모든 화면별 애니메이션은 자동 검증하지 않는다. 향후 실제 디자인 회귀가 반복될 때 고정된 환경의 대표 이미지 비교를 검토한다.

Sandpack 외부 런타임의 코드 실행, giscus 실제 로그인·댓글, 모바일 핀치/팬과 Safari·Firefox는 이 CI의 보증 범위가 아니다. 2차 검토에서는 실제 PhotoSwipe 개폐/포커스, Sandpack SDK 탭, 모바일 목차 좌표, 일반 공유 전환 효과, no-JS 브라우저 탐색, 로컬 HTTP 404도 자동 검증 범위에서 제외했다. 브라우저 테스트는 Chromium 두 viewport이며 서로 다른 브라우저 엔진 검증으로 부르지 않는다. 루트 경로 빌드의 실제 브라우저 검증은 `/blog` 대표 빌드로 대체되며, 루트 경로 생성은 하위 테스트와 실제 배포 설정의 postbuild 검사에서 확인한다.

실제 콘텐츠는 배포용 정적 검증이 담당한다. 특정 초안 데모를 브라우저에서 매번 구동하는 검사는 제거했으므로 데모 자체를 바꿀 때 필요하면 별도 수동 확인한다.

## 1차 검증 기록

- 변경 전 일반 E2E: 44개 통과, 로컬 Playwright 실행 요약 18.8초. 별도 번역 실행 시간은 이 값에 포함되지 않는다.
- 변경 후 `npm test`: 47개 통과, 로컬 Vitest 실행 요약 3.15초.
- 변경 후 `CI=1 npm run test:e2e`: 일반·번역 14개 모두 첫 시도에 통과, 로컬 Playwright 실행 요약 14.5초 (2 workers, 공통 빌드 포함).
- 실제 `posts.ts`의 날짜 정렬을 잠시 오름차순으로 바꾸자 새 `post-pages` 홈 테스트가 실패했다. 원래 구현을 복원했고 소스 변경은 남기지 않았다.
- lint·타입 검사·포맷 검사·`git diff --check` 통과. 스킬도 공식 `quick_validate.py` 검사 통과.
- `OMIT_DRAFTS=true BASE_PATH=/blog npm run build` 통과. 실제 공개 원문 17개, 공개 영어 번역 0개 상태의 영어 홈·양쪽 인덱스·legacy/초안 제외 산출물 검사도 통과했다.

위 시간은 macOS 로컬 실행 한 번의 기록이며 전후 워커 수도 같지 않아 CI 절감률로 해석하지 않는다. 1차 구조적 절감은 E2E 실행 50 → 14개, CI 빌드 3 → 2회였다. 2차에서는 빌드 횟수를 유지하고 E2E를 5개로 줄였다. 다음 GitHub Actions 실행에서 설치·빌드·테스트 단계 시간을 비교한다.

## 2차 검증 기록

- `npm test`: **49개 통과**, 로컬 Vitest 3.11초.
- `CI=1 npm run test:e2e`: **5개 모두 첫 시도 통과**, 로컬 Playwright 요약 12.4초, 2 workers.
- 404의 URL 언어 판별을 잠시 `ko`로 고정했을 때 새 SSR/hydration 통합 테스트가 영어 글/복귀 경로 검증에서 실패했다. 원본을 즉시 복원했고 애플리케이션 소스 변경은 남기지 않았다.
- lint·타입·포맷·`git diff --check` 통과. 공개 원문 17개/영어 0개 실제 콘텐츠 빌드와, 영어 픽스처를 포함한 E2E 빌드 모두 정적 HTML DOM 검사를 통과했다.
- 생성한 `frontend-testing` 스킬에도 필요성 → 중복 → 계층 순서와 API 경계·SSR/hydration·정적 HTML 검토 기준을 반영했다.

14개 실행의 14.5초와 5개 실행의 12.4초는 로컬 단일 실행 기록이다. 빌드 비용이 남으므로 테스트 개수 감소를 CI 시간 감소율로 환산하지 않는다. 전체 테스트 비용보다 테스트의 독립적인 보호 가치가 이번 삭제 기준이다.
